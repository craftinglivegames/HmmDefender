# HmmDefender

**Защита [OpenCode](https://opencode.ai) от «залипания» модели.**

Ловит вырожденное повторение в рассуждении модели (`hmm, hmm, hmm: hmm, hmm: …`),
обрывает генерацию, чистит историю и заставляет агента продолжить работу с конкретного шага.

## Проблема

Reasoning-модели иногда «залипают»: рассуждение превращается в бесконечный повтор,
и агент жжёт токены, пока не упрётся в лимит вывода. Выглядит это так:

```
hmm, hmm, hmm: hmm, hmm: hmm, hmm: hmm, hmm, hmm: hmm, hmm,
: hmm: hmm: hmm: hmm: hmm: hmm: hmm: hmm: hmm: hmm: hmm: ...
```

Плагин появился после реального случая в живой сессии OpenCode: одно сообщение модели
разрослось до **1 266 382 символов** сплошного «`: hmm: hmm: …`» — это примерно
полмиллиона потраченных впустую токенов и мёртвая сессия.

Ловятся три вида вырождения:

| Тип | Что повторяется | Пример |
| --- | --- | --- |
| `filler` | слова-заполнители | `hmm: hmm: hmm: hmm: …`, `хм, мм, эм …` |
| `word-period` | блок слов / целая фраза | одна и та же фраза 3+ раза подряд |
| `char-period` | блок символов без пробелов | `TheTheTheTheThe…` |

## Что делает плагин

1. **Следит** за потоком рассуждения модели в реальном времени.
2. **Обрывает** генерацию, как только находит петлю (`session.interrupt`).
3. **Продолжает работу** — отправляет агенту короткое уточнение («назови один конкретный
   следующий шаг и сделай его»), чтобы тот не просто встал, а доделал задачу.
4. **Чистит историю** — перед следующим запросом вырезает повторяющийся кусок из
   сообщений модели, чтобы она не «заражалась» собственным мусором.
5. **Профилактика** — добавляет в системный промпт короткое правило против повторов.

Всё это настраивается и отключается по частям (см. [Настройка](#настройка)).

## Установка

### Требования

- **OpenCode 2.x** (плагинный API V2: `ctx.event.subscribe`, `ctx.session.hook`, `ctx.session.interrupt`).
- **Node.js 22.18+** или новее — только для запуска тестов. Сам плагин исполняется внутри OpenCode (Bun).
- Сборка не нужна: OpenCode исполняет TypeScript напрямую.

### Способ 1. Глобально (рекомендуется)

Плагин будет работать во всех проектах. OpenCode автоматически сканирует каталог
`~/.config/opencode/plugins/` и загружает каждый подкаталог как плагин.

**Windows (PowerShell):**

```powershell
git clone https://github.com/craftinglivegames/HmmDefender.git `
  "$env:USERPROFILE\.config\opencode\plugins\hmm-defender"
```

**macOS / Linux:**

```bash
git clone https://github.com/craftinglivegames/HmmDefender.git \
  ~/.config/opencode/plugins/hmm-defender
```

> Если используется `XDG_CONFIG_HOME`, путь будет `$XDG_CONFIG_HOME/opencode/plugins/hmm-defender`.

Перезапустите OpenCode (или перезагрузите плагины) — этого достаточно.

### Способ 2. Только для проекта

Положите плагин в проект, чтобы он не влиял на остальные:

```
<проект>/.opencode/plugins/hmm-defender/
├── index.ts
├── detect.ts
└── package.json
```

```bash
mkdir -p .opencode/plugins
git clone https://github.com/craftinglivegames/HmmDefender.git \
  .opencode/plugins/hmm-defender
```

### Способ 3. Через `opencode.json`

Если плагин лежит в нестандартном месте, укажите путь явно (глобальный
`~/.config/opencode/opencode.json` или проектный `opencode.json`):

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": [
    "C:/Users/me/tools/HmmDefender"
  ]
}
```

С настройками прямо в конфиге:

```jsonc
{
  "plugins": [
    {
      "package": "C:/Users/me/tools/HmmDefender",
      "options": {
        "interrupt": true,
        "resume": true,
        "fillerMinHits": 10
      }
    }
  ]
}
```

### Проверка установки

1. Откройте OpenCode в любом проекте.
2. Убедитесь, что появились инструменты `hmm_defender_check` и `hmm_defender_status`
   (в Code Mode — через `search`, в обычном режиме — в списке инструментов).
3. Вызовите `hmm_defender_status` — он покажет настройки, счётчики и путь к журналу:

```json
{
  "enabled": true,
  "directory": "C:\\Users\\me\\project",
  "options": { "interrupt": true, "resume": true, "prevention": true, "pollText": false, "maxRescues": 3 },
  "totals": { "loops": 0, "rescues": 0, "repairs": 0 },
  "log": "C:\\Users\\me\\.config\\opencode\\plugins\\hmm-defender\\hmm-defender.log"
}
```

4. Проверьте сам детектор на «плохом» тексте:

```
hmm_defender_check(text: "hmm, hmm, hmm: hmm, hmm: hmm, hmm: hmm, hmm, hmm: hmm, hmm,")
```

```json
{ "loop": true, "kind": "filler", "ratio": 1, "repeats": 12, "period": 1, "cut": 0 }
```

Если плагин не появился — смотрите журнал OpenCode:
`~/.local/share/opencode/log/opencode.log`, ищите строки `loading plugin` / `failed to load plugin`.

**Если в журнале `Cannot find module '@opencode/plugin':**

```bash
cd ~/.config/opencode/plugins/hmm-defender
npm install @opencode/plugin
```

(в большинстве сборок OpenCode модуль подставляется сам, установка нужна только если
загрузчик его не нашёл).

### Обновление и удаление

```bash
cd ~/.config/opencode/plugins/hmm-defender && git pull     # обновление
rm -rf ~/.config/opencode/plugins/hmm-defender             # удаление
```

После обновления/удаления перезапустите OpenCode.

## Настройка

Параметры читаются из двух мест (второе важнее):

1. `config.json` рядом с плагином — скопируйте `config.example.json` → `config.json`
   и правьте под себя:

   ```bash
   cp config.example.json config.json
   ```

2. Объект `options` в секции `plugins` файла `opencode.json` (см. [способ 3](#способ-3-через-opencodejson)).

| Параметр | По умолчанию | Что делает |
| --- | --- | --- |
| `enabled` | `true` | Включён ли плагин целиком |
| `interrupt` | `true` | Обрывать генерацию при найденной петле |
| `resume` | `true` | Просить модель продолжить после обрыва |
| `prevention` | `true` | Добавлять правило против повторов в системный промпт |
| `pollText` | `false` | Дополнительно опрашивать текстовый вывод каждые 3 с (медленнее) |
| `maxRescues` | `3` | Сколько раз за сессию можно вмешиваться |
| `checkEvery` | `256` | Через сколько новых символов запускать полную проверку |
| `log` | `true` | Писать журнал |
| `debug` | `false` | Подробный журнал (каждая проверка) |
| `logPath` | `hmm-defender.log` | Путь к журналу |
| `resumeDelayMs` | `2500` | Пауза перед отправкой «продолжай» |
| `pollIntervalMs` | `3000` | Период опроса при `pollText: true` |

## Параметры детектора

Все пороги можно переопределить в `config.json` / `options`.

| Параметр | По умолчанию | Смысл |
| --- | --- | --- |
| `fillerMinHits` | `8` | Сколько слов-заполнителей подряд считать петлёй |
| `fillerMinRatio` | `0.5` | Доля заполнителей среди слов хвоста |
| `fillerWords` | `hmm, um, uh, хм, мм, …` | Список слов-заполнителей |
| `wordPeriodMax` | `64` | Максимальная длина повторяющегося блока (в словах) |
| `wordMinRepeats` | `3` | Сколько повторов блока считать петлёй |
| `wordSimilarity` | `0.8` | Доля совпавших слов в периоде (допуск на «дрожание») |
| `charPeriodMax` | `384` | Максимальная длина периода (в символах) |
| `charPeriodMin` | `3` | Минимальный период в символах |
| `charMinRepeats` | `4` | Сколько повторов блока в символах считать петлёй |
| `charSimilarity` | `0.8` | Доля совпавших символов в периоде |
| `minLoopChars` | `40` | Минимальная длина повторяющегося участка |
| `windowChars` | `2400` | Размер анализируемого хвоста текста |
| `maxScanChars` | `20000` | Сколько символов с конца сканировать в длинных сообщениях |

## Инструменты

| Инструмент | Назначение |
| --- | --- |
| `hmm_defender_check` | Прогнать произвольный текст через детектор и получить вердикт (`loop`, `kind`, `ratio`, `repeats`, `period`, `cut`). Удобно, чтобы подобрать пороги под свою модель. |
| `hmm_defender_status` | Настройки, счётчики (найдено петель / спасений / починенных блоков), статус шага по сессиям, путь к журналу. |

## Как это работает

```
поток событий OpenCode V2
        │  session.reasoning.delta  (куски рассуждения)
        ▼
  ┌─────────────┐   петля?    ┌───────────────────────┐
  │  detectLoop │ ──────────► │ ctx.session.interrupt │  генерация остановлена
  └─────────────┘             └───────────────────────┘
                                         │  +2.5 с
                                         ▼
                             уточнение «продолжай с шага N»
                                         │
                                         ▼
                   хук context: вырезать мусор из истории + правило в system
```

Детали:

- Поток рассуждения собирается по сообщениям и хранится только хвостом (20 000 символов) —
  память не растёт даже на многочасовых сессиях.
- Полная проверка запускается не на каждый кусок, а каждые `checkEvery` символов
  (плюс быстрая эвристика на заполнители) — нагрузка на CPU минимальна.
- Детектор ищет период повтора с допуском: реальные петли «дрожат» (лишняя запятая,
  обрезанное слово), поэтому сравнение идёт по доле совпадений, а не один-в-один.
- История чинится в хуке `context` — то есть прямо перед отправкой запроса модели,
  не затрагивая сохранённую переписку.
- Если в проекте оказалось несколько экземпляров плагина (OpenCode грузит плагин
  на каждый каталог проекта), повторное вмешательство в одну и ту же петлю блокируется
  общим журналом спасений.

## Чувствительность и подбор порогов

- **Ложные срабатывания.** Обычные «hmm, hmm» (2–3 раза), код с отступами,
  markdown-таблицы, списки похожих строк и нормальные рассуждения петлёй не считаются —
  это покрыто тестами.
- **Слишком часто срабатывает** → поднимите `fillerMinHits` до `12–15` и `wordSimilarity` до `0.9`.
- **Пропускает петли** → снизьте `fillerMinHits` до `5–6` или `wordSimilarity` до `0.7`.
- Быстрый способ проверить новый порог — `hmm_defender_check` на реальном фрагменте.

## Ограничения

- В поток событий OpenCode V2 попадает **только рассуждение** (`session.reasoning.delta`).
  Петля в обычном текстовом ответе ловится на следующем запросе — чисткой истории.
  Для контроля текста почти в реальном времени включите `pollText: true` (дороже по CPU).
- Обрыв генерации не отменяет уже выполненные инструменты — их результат сохраняется.
- Прерывание срабатывает не мгновенно: провайдер может ещё какое-то время отдавать
  поток, но текст после обрыва уже не превращается в полезный ответ.
- Плагин рассчитан на OpenCode 2.x. На OpenCode 1.x API плагинов другой
  (`ctx.session`/`ctx.event` отсутствуют), и плагин не загрузится.

## FAQ

**Оборвёт ли плагин полезную работу?**
Обрывается только текущая генерация, когда она уже выродилась в повтор. Выполненные
инструменты и файлы не затрагиваются, дальше агент продолжает с того же места.

**Можно ли сначала посмотреть, не будет ли ложных срабатываний?**
Да: `hmm_defender_check` на ваших текстах, либо временно `"interrupt": false` —
плагин будет только писать в журнал и чистить историю, но не обрывать генерацию.

**Работает ли с любой моделью?**
Да, плагин не зависит от провайдера: он смотрит поток событий OpenCode, а не ответы API.

**Конфликтует ли с другими плагинами?**
Нет. Он добавляет один блок в системный промпт (можно отключить `"prevention": false`)
и один хук `context` для чистки истории.

**Куда пишется журнал?**
`hmm-defender.log` рядом с плагином (ротация при 256 КБ). Путь виден в `hmm_defender_status`.
